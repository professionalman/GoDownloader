## 8. Runtime Constructor Semantics (`app.New`)
- Signature: `func New(ctx context.Context, cfg *config.Config, opts ...Option) (*App, error)`
- Validates non-nil configuration.
- Supports options, e.g. `WithDBPath(path)` for isolated test databases (defaults to `./downloader.db`).
- Constructs all durable components in dependency order.
- Utilizes an internal `cleanupStack` that runs LIFO rollback if any constructor step fails, preventing resource leaks.
- Does NOT start background loops or scheduling (that is deferred to `Start`).

---

## 9. Start Semantics (`app.Start`)
- Signature: `func (a *App) Start(ctx context.Context) error`
- Atomic guard: Uses `atomic.Bool` (`started`) to enforce that `Start` can only be called once. Repeated calls return an explicit error.
- Enforces that stopped runtimes cannot be restarted.
- Launches the Tracker background runner in a dedicated goroutine: `go a.trackerService.Run(ctx)`.
- Calls `a.manager.StartBackgroundTasks(ctx)`, executing all recovery and scheduling loops in verified foundation order.

---

## 10. Shutdown Semantics (`app.Shutdown`)
- Signature: `func (a *App) Shutdown(ctx context.Context) error`
- Concurrency-safe and strictly idempotent via `sync.Once`.
- Executes verified foundation shutdown order:
  1. `manager.Stop()`: Halts network reconciler, stops scheduler loop, stops progress monitor, cancels active job contexts, and signals ytdlp engine shutdown.
  2. `processSupervisor.Shutdown(ctx)`: Closes Win32 Job Object handles with `KILL_ON_JOB_CLOSE`, ensuring all owned child process trees terminate within deadline.
  3. `db.Close()`: Closes SQLite database strictly after manager and supervisor persistence operations finish.
- External daemons (qBittorrent, aria2) remain untouched as unowned processes.

---

## 11. Context Ownership
- **Construction Context (`app.New`):** Passed for initialization tasks (e.g. MasterKey decryption proof and tool ledger validation).
- **Runtime Operational Context (`app.Start`):** Root process lifecycle context passed to long-running background tasks (`trackerService.Run`, `manager.StartBackgroundTasks`). When cancelled by OS signal or host shutdown, cancels background activity.
- **Shutdown Timeout Context (`app.Shutdown`):** Bounded context (e.g. 5-10s) specifically allocated for graceful teardown and process tree termination deadlines.
- Request contexts are not stored in long-lived runtime state.

---

## 12. Partial-Construction Failure Cleanup
- Managed via `cleanupStack` in `app.New`.
- If database opens successfully but master key verification fails, `cleanupStack` invokes `db.Close()`.
- If `processSupervisor` is allocated but engine initialization fails, `cleanupStack` terminates supervisor process trees and closes the database.
- Zero open file handles or dangling processes can leak on initialization error.

### Accessor Removals and Justifications
During the final gate audit, 9 speculative/uncalled accessors were removed to satisfy YAGNI and enforce strict encapsulation:
1. `DB()` — Removed. Host should not directly touch database connections. Teardown and migration are completely managed by `App`.
2. `ProcessSupervisor()` — Removed. Host does not manipulate process trees directly. `ProcessSupervisor` is wired to `ytdlp` engine internally and reaped by `App.Shutdown`.
3. `ResourceGovernor()` — Removed. Internal scheduling subsystem managed entirely between `Manager` and `Scheduler`.
4. `Scheduler()` — Removed. Internal dispatch loop managed entirely by `Manager`.
5. `Config()` — Removed. Host already instantiates and owns `cfg *config.Config`.
6. `Storage()` — Removed. Host router takes `Categories()` (`storage.ICategoryRepository`), not `StorageService`.
7. `ToolManager()` — Removed. External tool discovery and ledger revalidation occur entirely within `App.New`.
8. `Started()` — Removed. Internal lifecycle flag; tests inspect package-internal field `a.started` directly.
9. `Stopped()` — Removed. Internal lifecycle flag; tests inspect package-internal field `a.stopped` directly.

### Lifecycle State Semantics
`App` coordinates lifecycle through a protected state machine (`mu sync.Mutex`):
- `Start(ctx)`: Transitions from `NEW` to `STARTED`. Returns explicit error if already started or if stopped/stopping. Starts tracker goroutine with dedicated cancellation context and channel (`trackerDone`), then triggers `manager.StartBackgroundTasks(ctx)`.
- `Start` after `Shutdown`: Rejects immediately with `"cannot start stopped application runtime"`.
- `Duplicate Start`: Rejects immediately with `"application runtime already started"`.
- `Shutdown` before `Start`: Valid and safe. Safely closes database connection and transitions state directly to `STOPPED`. Subsequent `Start` calls are rejected.
- `Start` racing with `Shutdown`: Protected under `a.mu`. If `Shutdown` sets `stopping = true` first, `Start` rejects immediately. If `Start` sets `started = true` first, `Shutdown` observes initialized tracker/manager channels and drains them cleanly.

### Concurrent Shutdown Join Semantics & Joiner Contract
- The first caller that transitions the state to `stopping = true` **owns** teardown. Its supplied context governs `ProcessSupervisor` termination deadlines and tracker drain waits.
- Subsequent concurrent callers are **joiners**. Joiners unconditionally wait on `<-a.shutdownDone` and return the final stored `a.shutdownErr`.
- Joiners ignore their own context cancellation. A joiner's context does NOT own teardown; returning early upon joiner context cancellation would create a false signal that shutdown completed, which could allow a desktop shell or signal handler to exit while background persistence or process cleanup is still actively running.
- Invariant verified: When ANY `App.Shutdown` call returns after observing an active shutdown, the shared teardown has completely finished.
- Verified deterministically by `TestApp_Shutdown_Concurrent_Join_IgnoresContextCancellation`.

### Shutdown Error & Cancelled First-Owner Behavior
- Teardown stages are strictly sequenced:
  1. `trackerCancel()` is invoked and `<-trackerDone` drained before DB close.
  2. `manager.Stop()` stops scheduler, progress monitor, and cancels active jobs.
  3. `processSupervisor.Shutdown(ctx)` terminates child process trees in Win32 Job Objects.
  4. `db.Close()` closes SQLite database connection.
- Inspection of `ProcessSupervisor.Shutdown(ctx)` confirmed that it initiates termination of **every** owned process (`for _, p := range procs { _ = p.Terminate() }`) immediately upon entry, **before** inspecting `ctx.Done()`. Even when called with an already-cancelled context, process tree termination is initiated.
- In `App.Shutdown`, `db.Close()` executes in Step 4 regardless of whether `ProcessSupervisor.Shutdown` returns an error or context deadline. Errors are combined via `errors.Join`. No unclosed database handles or orphan processes remain.

### Partial-Start & Partial-Construction Cleanup
- `app.New` uses `cleanupStack` (LIFO rollback): if any step fails during initialization, all previously opened resources (e.g. database, supervisor) are closed before returning an error.
- `app.Start` launches the tracker background goroutine with its own cancellation context and wait channel before triggering manager background tasks.

### Tracker & Background Goroutine Ownership
- `trackerService.Run(ctx)` is runtime-owned.
- In `App.Shutdown`, the tracker cancellation context is cancelled and `<-a.trackerDone` is awaited before `db.Close()`. No background query can execute against a closed SQLite handle.

### Server Startup & Listener Ordering
- `cmd/server/main.go` uses `run() error` pattern:
  - `application, err := app.New(ctx, cfg)`
  - `defer func() { application.Shutdown(...) }()`
  - `application.Start(ctx)`
  - `api.CheckNonLoopbackBind(...)`
  - `router := api.NewRouter(...)`
  - `server.ListenAndServe()`
- The HTTP listener is only bound after `app.New` and `app.Start` succeed. On any startup failure, deferred `application.Shutdown` executes cleanly before `log.Fatalf` terminates the process.

### Event Bus Identity
`App.EventBus()` returns the exact `*events.InMemoryBus` instance passed to `job.Manager`. SSE handlers and future desktop event adapters share this identical bus instance without bridging or duplicating events.
