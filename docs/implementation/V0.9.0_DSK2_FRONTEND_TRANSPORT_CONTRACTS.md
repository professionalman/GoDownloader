## 7. Selected Abstraction and Why
The chosen abstraction establishes a clean **pluggable client interface** (`BackendClient`) partitioned by domain, coordinated through a **stable application facade** (`web/src/api.ts`):
- **Interface Structure:** Rather than a monolithic 46-method flat interface, `BackendClient` organizes operations into 7 focused domain interfaces matching the backend architecture:
  - `jobs: JobsOperations`
  - `queue: QueueOperations`
  - `settings: SettingsOperations`
  - `categories: CategoriesOperations`
  - `tracker: TrackerOperations`
  - `mediaAuth: MediaAuthOperations`
  - `sync: SyncOperations`
- **Zero Session/CSRF Concepts on BackendClient:** A future desktop client communicates via in-process IPC and has no need for cookies, CSRF tokens, or session bootstrap. All session bootstrap (`initSession`) and CSRF management are encapsulated strictly within `HttpBackendClient` and browser entry points.
- **Why this design was chosen:**
  1. **Minimal Churn:** `web/src/api.ts` retains all exported domain function signatures and types, delegating to `getBackendClient()`. React components required ZERO changes to their import paths or call sites.
  2. **Strict Transport Neutrality:** Methods receive and return typed domain objects (`Job`, `QueueSnapshot`, `SyncSnapshot`). No URL paths, HTTP verbs, headers, or cookies leak into the contract.
  3. **Wails Ready:** Future milestone `DSK-3` can implement `BackendClient` by binding directly to Go struct methods via Wails v3 IPC without parsing HTTP strings or inventing fake cookies.
  4. **Testability:** A minimal test-only in-memory fake client (`FakeBackendClient`) can be injected via `setBackendClient(fake)` to test React components without a network server or mocking `fetch`.

---

## 8. Alternatives Rejected Under YAGNI
1. **Generic Dependency Injection Framework (e.g. InversifyJS, TSyringe):** Rejected as massive over-engineering for a client with two planned implementations (HTTP and Wails).
2. **Command Dispatch String Pattern (`client.execute("jobs.create", payload)`):** Rejected because it loses compile-time type safety and requires manual payload unpacking.
3. **Mega-Interface (46 methods flat on a single interface):** Rejected because it forces test fakes and mock implementations to implement all 46 methods or resort to unsafe type casting.
4. **Desktop REST Emulation Layer:** Rejected because translating desktop IPC through fake HTTP URLs would preserve HTTP as the internal desktop architecture.
5. **SessionOperations on BackendClient:** Rejected during the purity gate because in-process desktop IPC does not have or need sessions, cookies, or CSRF tokens.

## 10. Stable `api.ts` / Facade Responsibilities
`web/src/api.ts` serves strictly as the stable, typed application facade:
- Exposes `getBackendClient()` and `setBackendClient(client)` to support runtime transport switching.
- Exports all public domain functions (`createJob`, `getJobs`, `getSyncSnapshot`, `subscribeEvents`, etc.) delegating directly to `getBackendClient().<domain>.<method>()`.
- Re-exports `ApiResponseError`, `BackendClient`, `EventSubscription`, and `EventSubscribeOptions`.
- **Zero HTTP Implementation Details:** Does not export `authFetch`, `initSession`, `connectSSE`, `setCsrfToken`, or `getCsrfToken`. Tests requiring low-level HTTP assertions import those directly from `web/src/transport/http`.

---

## 11. HTTP Adapter Responsibilities
`web/src/transport/http.ts` (`HttpBackendClient`) encapsulates all browser HTTP wire concerns:
- Base path configuration (`API_BASE = '/api/v1'`).
- CSRF cookie parsing (`godownloader_csrf`) and `X-CSRF-Token` header injection for mutating requests.
- Session bootstrap via `GET /api/v1/auth/session` and automatic single-retry re-bootstrap on HTTP 401.
- REST endpoint URL construction and JSON request/response serialization.
- Server-Sent Events (`EventSource`) lifecycle management via `HttpEventSubscription`, including cursor query parameterization (`/api/v1/events?cursor=C`).

---

## 12. Session and CSRF Separation
- Session bootstrap (`initSession`) and CSRF tokens (`X-CSRF-Token`) are categorized as adapter-specific mechanics.
- In HTTP browser mode, `web/src/main.tsx` invokes `initSession()` proactively before mounting React.
- If a mutating request occurs when `cachedCsrfToken` is null, `authFetch` automatically initializes the session.
- If session expiration or server restart yields HTTP 401, `authFetch` automatically calls `initSession()` once and retries the request with the refreshed CSRF token.
- In desktop native mode, in-process IPC is immune to cross-site request forgery and does not require session cookies; `BackendClient` requires zero session methods.
- Zero React feature components manipulate CSRF tokens or cookies directly.

## 13. Event Subscription Contract
The event streaming boundary separates application event semantics from SSE transport mechanics:
- **Subscription Handle (`EventSubscription`):**
  ```typescript
  export interface EventSubscription {
    close(): void;
  }
  ```
- **Subscription Options (`EventSubscribeOptions`):**
  ```typescript
  export interface EventSubscribeOptions {
    onEvent: (eventType: string, job: Job, seq?: number) => void;
    onSyncRequired?: (payload: { cursor: number; reason: string }) => void;
    getCursor?: () => number | undefined;
    onConnected?: () => void;
    onError?: (err?: unknown) => void;
  }
  ```
- `HttpEventSubscription` wraps browser `EventSource`, implementing `close()` to safely unbind `onConnected`/`onError` listeners, close the `EventSource`, and null internal references.
- In `web/src/App.tsx`, `activeSubRef = useRef<EventSubscription | null>(null)` replaced `activeEsRef = useRef<EventSource | null>(null)`. Component consumes `subscribeEvents` directly, eliminating `EventSource`, `addEventListener`, and `removeEventListener` from React components.

## 14. StateSync Contract
- Authoritative snapshot retrieval (`sync.getSnapshot()`) returns a typed `SyncSnapshot` containing `{ cursor, jobs, queue, timestamp }`.
- Live event delivery provides monotonic sequence numbers (`seq`).
- `App.tsx` retains monotonic cursor deduplication:
  `if (seq !== undefined && seq > 0 && seq <= lastAppliedCursorRef.current) return;`
- Gaps or buffer overflows trigger `onSyncRequired({ cursor, reason })`, which increments `rehydrationGenRef.current`, closes the active subscription, fetches an authoritative snapshot, and reconnects from the new cursor.

---

## 15. Synchronization Ordering & Race Preservation
The exact subscribe-before-replay semantics from FND-2B are preserved:
1. **Initial Mount Sequence:**
   - Mount effect triggers `getSyncSnapshot()`.
   - Concurrently, event stream effect establishes subscription with `cursor = 0` (`lastAppliedCursorRef.current`).
   - When snapshot resolves:
     - `lastAppliedCursorRef.current = snapshot.cursor`.
     - `setJobs(snapshot.jobs)`, `setQueueSnapshot(snapshot.queue)`.
     - If `snapshot.cursor > 0`, `setStreamTrigger((t) => t + 1)` is called.
   - Incrementing `streamTrigger` tears down the initial subscription and establishes a new subscription starting from `snapshot.cursor`.
2. **Race-Safety Reasoning:**
   - Any event received before or during snapshot resolution with `seq <= lastAppliedCursorRef.current` is idempotently filtered out by monotonic deduplication.
   - Any event received after snapshot resolution with `seq > lastAppliedCursorRef.current` updates state and advances the cursor.
   - If a ring-buffer gap occurs on the backend, the backend emits `sync.required`, which immediately closes the stream, increments `rehydrationGenRef` (fencing out stale snapshot responses), fetches a fresh snapshot, and reconnects.

---

## 16. Unsubscribe and Reload Lifecycle
- When `App.tsx` re-renders due to `streamTrigger` or unmounts, the `useEffect` cleanup hook executes:
  ```typescript
  return () => {
    if (activeSubRef.current === sub) {
      sub.close();
      activeSubRef.current = null;
    }
  };
  ```
- In `HttpEventSubscription`, `close()` is idempotent, unbinds open/error listeners, and calls `EventSource.close()`.
- Verified by focused test G in `web/src/transport/transport.test.ts`: unsubscribing stops event dispatch immediately and releases listeners, preventing listener multiplication.

---

## 17. Error Handling
- Transport-neutral error class `ApiResponseError` carries:
  - `code: string` (e.g. `'INSUFFICIENT_DISK_SPACE'`, `'NOT_FOUND'`, `'UNAUTHORIZED'`).
  - `message: string` (human-readable error description).
- HTTP status codes are translated by `HttpBackendClient` into `ApiResponseError`.
- Future desktop Go errors will be wrapped in `ApiResponseError` with identical error codes, allowing UI components (e.g. disk space warnings in `TorrentFileSelector`) to behave identically across web and desktop.

## 18. Transport Selection Mechanism
- Default client: `httpBackendClient` (singleton instance of `HttpBackendClient`).
- Registry (`web/src/transport/index.ts`):
  - `getBackendClient(): BackendClient`: returns active client.
  - `setBackendClient(client: BackendClient): void`: swaps active client.
  - `resetBackendClient(): void`: resets to default `httpBackendClient`.
- Future DSK-3 frontend desktop bootstrap / entrypoint installs the native `BackendClient` before invoking the shared React mount path.
- Tests call `resetBackendClient()` in `afterEach()` to guarantee zero test leakage.

## 19. Frontend Host Bootstrap Boundary
To decouple the React application mounting lifecycle from browser HTTP mechanics, the mount boundary is cleanly partitioned:

```text
                         shared React mount (bootstrap.tsx: mountApp)
                                     |
                       +-------------+-------------+
                       |                           |
                browser entry              future desktop entry
                 (main.tsx)                 (e.g. desktop.tsx)
                       |                           |
              initSession()              setBackendClient(native)
                       |                           |
                  mountApp()                   mountApp()
```

- **Browser Host Entry (`web/src/main.tsx`):**
  - Imports `mountApp` from `./bootstrap` and `initSession` from `./transport/http`.
  - Proactively triggers `initSession()` to prime CSRF cookie/header state.
  - Calls `mountApp()` immediately.
  - Failure behavior: Even if `initSession()` fails (backend offline at startup), `mountApp()` still mounts React cleanly. `getSyncSnapshot()` catches the offline condition and renders the connection error UI rather than failing with a blank page.
- **Shared Application Mount (`web/src/bootstrap.tsx`):**
  - Exports `mountApp(options?: MountAppOptions): Root`.
  - Framework-neutral: imports only React `StrictMode`, `createRoot`, `./index.css`, and `./App`.
  - Zero transport imports: imports NO `fetch`, NO `EventSource`, NO `initSession`, NO cookies, NO CSRF.
- **Future Desktop Host Seam:**
  - Future DSK-3 desktop entrypoint imports `setBackendClient` and `mountApp`.
  - Calls `setBackendClient(desktopBackendClient)` synchronously before `mountApp()`.
  - Invokes `mountApp()`.
  - React mounts with the native backend active from line 1.
  - Verified by Test M: Mounting `App` after `setBackendClient(fake)` executes with ZERO `fetch` and ZERO `EventSource` invocations.
- **Import Side-Effect Audit:**
  - Verified by Test N: Importing `bootstrap.tsx`, `api.ts`, `transport/index.ts`, or `App.tsx` performs zero network requests and creates zero EventSource streams.
