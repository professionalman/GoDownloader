#### Diagnostic Release Disposition Policy
- **Internal V0.9.0 Engineering Preview:** Diagnostic surfaces may remain active in full to support deterministic test verification, headless smoke tests, and reload acceptance.
- **Before Any Public Redistributable Build:** Explicitly review and either:
  1. Remove;
  2. Gate behind build tags (`//go:build dev || diagnostic`); or
  3. Formally approve individual safe, read-only diagnostics (e.g. `--print-data-root`, `GetBackendInstanceID`).
- **Trigger-Capable Classification:** `--trigger-quit`, `--trigger-reload`, `--emit-diagnostic-event`, `--test-dialog`, and corresponding native IPC methods that mutate or drive runtime state are classified as **strictly requiring public-build disposition** before public distribution.
