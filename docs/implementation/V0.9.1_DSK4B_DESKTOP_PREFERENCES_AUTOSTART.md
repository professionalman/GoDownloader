### 2. Canonical Mapping

`ROADMAP.md` Milestone `DESK-2 — Lifecycle / Packaging` specifies:
> *"Tray/background/quit, opt-in autostart, recovery UX, support bundle, installer fixtures and web-mode fallback."*

Slice `DSK-4B` implements user-configurable desktop preferences and Windows autostart integration:
1. `close_to_tray` preference persisted in SQLite `app_settings` (default `true`), preserving DSK-4A hide behavior by default.
2. When `close_to_tray` is set to `false`, clicking window close ('X') terminates the desktop application cleanly via the existing deferred `App.Shutdown` path.
3. Live updates to `close_to_tray` immediately update the running `DesktopLifecycle` coordinator without requiring application restart.
4. "Start GoDownloader with Windows" is strictly opt-in (default `false`). Operational truth is derived directly from the Windows Registry (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`) via Wails `AutostartManager`. Zero duplicate state is kept in SQLite.
5. Autostart registers GoDownloader with the internal `--background` CLI argument, ensuring autostart launches hidden in the system tray without stealing focus or displaying a window.
6. Secondary launch distinction: secondary launch with `--background` does NOT restore or steal focus from the primary instance; normal secondary launch restores and focuses the primary instance.
7. Browser mode remains platform-truthful: desktop lifecycle preferences are omitted when connected to a standalone server.

### 6. Settings Architecture & Persistence

- Key: `KeyCloseToTray = "close_to_tray"` defined in `internal/settings/service.go`.
- Default: `DefaultCloseToTray = true`.
- Storage: Persisted in SQLite table `app_settings` with timestamped updates.

### 7. Pinned Wails Executable Semantics & Autostart Architecture

- Pinned version: `github.com/wailsapp/wails/v3 v3.0.0-beta.23`.
- Implementation: `wailsApp.AutostartManager`.
- Resolution: `resolvedExecutable()` invokes `os.Executable()`, followed by `filepath.EvalSymlinks()`.
- Windows enable: Writes to `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`:
  - Name: `godownloader` (slug derived from `application.Options.Name`).
  - Value Data: `"<resolved_executable_path>" "--background"`.
- **Critical Architectural Consequence:**
  - Calling `AutostartManager.Enable()` from a Go test process registers the temporary test binary (e.g. `desktop.test.exe`).
  - Testing autostart in `autostart_integration_test.go` verifies Wails controller mechanics on a test process.
  - True production acceptance requires driving the actual `bin\GoDownloader.exe` production binary, ensuring the registry value points to the real application executable.

### 9. Autostart `IsEnabled` Semantics & Limitations

- Pinned Wails Windows implementation searches registry entries in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` whose first command token resolves to the current executable.
- It does **not** validate subsequent command line arguments (e.g., `--background`).
- Therefore, `autostartEnabled == true` strictly means: *"A Windows login registration exists for this executable."*
- GoDownloader always writes `--background` when enabling autostart.
- Limitation: If a portable `.exe` is moved without re-toggling autostart, the registry will hold an orphaned path until updated. (This will be fully addressed in DSK-4D when installed to a static directory).

### 14. `--background` Implementation

- In `cmd/desktop/main.go`:
  ```go
  startBackground := false
  for _, arg := range os.Args[1:] {
      if arg == "--background" {
          startBackground = true
          break
      }
  }
  ```

- Passed to `application.WebviewWindowOptions.Hidden: startBackground`.
- Fallback: If `startBackground` is requested but system tray configuration failed, `showMainWindow(mainWindow)` is called to prevent headless zombie state.

### 15. Normal vs Background Second-Instance Distinction

- `application.Options.SingleInstance.OnSecondInstanceLaunch`:
  ```go
  OnSecondInstanceLaunch: func(data *application.SecondInstanceData) {
      if secondLaunchHandler != nil {
          secondLaunchHandler(data)
      }
      hasBg := false
      for _, arg := range data.Args {
          if arg == "--background" || strings.HasPrefix(arg, "--set-") || strings.HasPrefix(arg, "--trigger-") || strings.HasPrefix(arg, "--emit-") {
              hasBg = true
              break
          }
      }
      if !hasBg {
          showMainWindow(mainWindow)
      }
  }
  ```
- Normal second launch restores and focuses the primary instance.
- `--background` second launch exits quietly with code 0 and does **not** restore or steal focus from the primary instance.
