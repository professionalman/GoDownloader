## 2. Consolidated Startup Lifecycle

From source verification in `cmd/server/main.go` and `internal/job/manager.go`, the authoritative startup order is:

```
[1. Process Start & Configuration]
   - Parse CLI flags and environment variables
   - Initialize config.Config, ListenAddr, DownloadDir, DataDir

[2. SQLite Database Open & Migrations] (database.New)
   - Pre-migration safety check: verify existing SQLite file
   - If pre-v0.8 database exists: create VACUUM INTO .pre-v08.bak backup
   - Validate backup integrity via PRAGMA quick_check and table check (fails closed before DDL)
   - Execute transactional migrations up to V0.8 FND-1 schema

[3. Repository Instantiation]
   - Construct Job, Queue, Settings, Secret, Tracker, Category, and Execution repositories

[4. Master Key & SecureStore Initialization] (securestore.NewDefaultMasterKeyManager)
   - ResolveCipher: check Windows Credential Manager -> candidate legacy env -> fresh generation
   - Cryptographically prove candidate key decrypts existing secrets (fails closed before API listener)
   - Construct AES-256-GCM SecureStore and SettingsService

[5. ToolManager Discovery & Revalidation] (toolmanager.New)
   - Register tool configs (yt-dlp, ffmpeg, aria2, qbittorrent)
   - Revalidate active records from tool ledger
   - Probe executables and daemon endpoints

[6. Subsystem & Engine Initialization]
   - MediaAuthService: cleanup stale temp files
   - StorageService: category repository, settings service, disk preflight
   - Aria2 Engine: register in engine registry
   - ProcessSupervisor: create process tree supervisor
   - yt-dlp Engine: inject resolved paths, auth provider, and processSupervisor
   - qBittorrent Engine: register and perform initial health check
   - EventBus, TrackerService, SSEHandler

[7. Job Manager & Governor Construction]
   - Construct Manager and inject repositories, storage, and settings
   - Construct ResourceGovernor with dynamic settings limit provider
   - Construct Scheduler and wire ResourceGovernor
   - Wire Scheduler into Manager

[8. Manager Background Startup] (Manager.StartBackgroundTasks)
   a. Reconcile FinalizationJournal: recover pending finalization records BEFORE workdir cleanup
   b. Recover Jobs: reconnect to running engine downloads; hydrate state into activeJobs
   c. Reconstruct ResourceGovernor: rebuild active leases from activeJobs before scheduler starts
   d. Reconcile Network Policies and process pending engine cleanups
   e. Cleanup Stale WorkDirs: delete abandoned directories while preserving active/queued jobs
   f. Cleanup Stale Queue: reconcile queue rows with durable job state
   g. Start Scheduler: begin scheduling loop and kick initial scan
   h. Start Progress Monitor: launch periodic engine polling loop

[9. Security Enforcement & Network Binding]
   - CheckNonLoopbackBind: verify bind address is loopback (fails closed on non-loopback)
   - Construct SecurityManager and Router with Host validation, CSRF, and session auth
   - Start HTTP Server: server.ListenAndServe()
```

### Invariant Checks Passed:
- **A. Backup Safety:** Pre-v0.8 backup failure occurs before any DDL mutation.
- **B. Master Key Safety:** Key mismatch or failure aborts boot before exposing the API listener.
- **C. Finalization Before Cleanup:** Journal reconciliation runs before workdir cleanup.
- **D. Recovery Before Scheduling:** Jobs reattached before scheduler loop launches.
- **E. Governor Reconstruction:** Active jobs reconstructed into governor before scheduler admits work.
- **F. ToolManager Readiness:** Tool paths and ledger revalidated before engine execution.
- **G. ProcessSupervisor Injection:** Supervisor wired to yt-dlp engine before any download starts.
- **H. Bound Surface Integrity:** All backend subsystems ready before HTTP listener opens.

## 3. Consolidated Shutdown Lifecycle

From source verification in `cmd/server/main.go` and subsystem defers (LIFO order):

```
[1. Termination Signal Received] (SIGINT / SIGTERM)
   - Cancel root context (ctx)
   - HTTP server.Close() immediately shuts down listener (stops incoming requests)

[2. Defers Execute in Reverse Order]
   a. Manager.Stop() runs first:
      - Stop network reconciler
      - Stop scheduler (no new jobs dispatched)
      - Stop progress monitor loop
      - Active download states safely flushed to DB
   b. ProcessSupervisor.Shutdown(shutdownCtx):
      - Terminate all remaining owned process trees via Job Objects
      - Wait for child processes to exit cleanly within 5s deadline
   c. db.Close():
      - SQLite database closed only AFTER all manager and process operations have persisted
   d. cancel():
      - Root context cleanup
```

### Invariant Checks Passed:
- New admissions halt immediately.
- Owned child process trees (`yt-dlp` + `ffmpeg`) are reaped cleanly.
- External daemons (`aria2`, `qBittorrent`) remain untouched.
- Database remains open and accessible until all lifecycle persistence completes.

## 4. Cross-Foundation Integration Audit

### FND-1: Durable Execution Schema
- Primary durable entities: `jobs`, `job_queue` (`retry_count`, `not_before`), `job_executions`, `http_checkpoints`, `http_checkpoint_segments`, `tool_records`, `event_cursors`, `finalization_records`.
- Backup handling preserves existing valid backups, recreates zero-byte backups, and fails closed on corrupted backups.
- No transient resource permits or wait states are persisted in SQLite.

### FND-2A: Finalization Recovery
- Lifecycle states: `prepared` $\to$ `in_progress` $\to$ `validated` $\to$ `db_committed` $\to$ `cleanup_pending` $\to$ `complete`/`failed`.
- Exact destination resolution, collision avoidance, and digest validation are enforced.
- In-progress finalization with missing staging file preserves destination if valid, preventing destructive overwrites.

### FND-2B: StateSync
- Global monotonic event cursor backed by `event_cursors` table (`scope = 'global'`).
- Serialized cursor advancement via `execRepo.cursorMu` prevents transaction deadlocks.
- High-frequency engine progress ticks send `Sequence: 0` (ephemeral), while durable state transitions advance the cursor exactly once.
- Snapshot rehydration returns `{cursor, jobs, queue, timestamp}` with generation fencing.

### FND-3A & FND-3B: Security & Master Key
- Local loopback enforcement rejects non-loopback binds (`127.0.0.1`, `::1` only).
- Host header validation prevents DNS rebinding attacks.
- All protected `/api/v1` routes require session authentication. Mutating protected routes additionally require CSRF validation (`X-CSRF-Token`). `/api/v1/auth/session` is the intentional session-bootstrap exception and remains subject to the established Host/Origin security policy.
- Windows Credential Manager stores 32-byte master key with AES-256-GCM encryption and AAD (`scope\0owner\0field`).
- Legacy environment keys migrate to OS store with read-back verification; plaintext env fallback is rejected on Windows.

### FND-4A & FND-4B: ToolManager & ProcessSupervisor
- ToolManager provides single authoritative path resolution and health verification for `yt-dlp`, `ffmpeg`, `aria2`, and `qbittorrent`.
- `ProcessSupervisor` owns child process trees:
  - Windows Job Object creation with `CREATE_SUSPENDED` flag.
  - Process assignment and `IsProcessInJob` verification before thread resumption.
  - Zero application instructions execute uncontained.
  - Idempotent termination reaps full process tree (including grandchild `ffmpeg` processes).

### FND-5A & FND-5B: Scheduler Policy & ResourceGovernor
- Deterministic queue ranking (`RankQueuedJobs`) using multi-tier total ordering: Run Now $\to$ effective aging priority $\to$ manual position $\to$ enqueue timestamp $\to$ JobID.
- Aging is monotonic, deterministic, restart-safe, and prevents starvation of low-priority jobs.
- `ResourceGovernor` is the single authority for global active transfer capacity and per-engine limits (`ytdlp = 2`).
- Head-of-line non-blocking scan allows eligible downloads to proceed when the top candidate is blocked by engine capacity.
- Run Now jobs receive top queue precedence but strictly respect hard governor limits without oversubscription.
- `yt-dlp` safely holds its transfer and engine permit for its entire subprocess lifetime (including FFmpeg processing).
- `qBittorrent` releases transfer capacity upon entering `StatusSeeding`, unblocking queued downloads.
- On failed engine pause, the governor lease is safely retained.

## 6. Concurrency & Lock Order Review

| Subsystem | Mutex | Lock Invariant |
|---|---|---|
| `ResourceGovernor` | `governor.mu` | **Leaf Lock:** Guards only in-memory primitive maps/counters. Never calls external functions, manager, database, or engines while holding lock. |
| `Manager` | `manager.mu` | Unlocked before calling `gov.Release(id)` in `removeActive(id)`. No lock inversion possible. |
| `Scheduler` | `scheduler.mu` | Guards in-flight reservations and timers. Evaluates candidates and calls `governor.TryAcquire` without holding `manager.mu`. |
| `ProcessSupervisor` | `supervisor.mu` | Guards process registry map. Process execution and process termination do not wait on manager locks. |

**Audit Result:** No cyclic dependencies or inverted lock order across subsystems.
