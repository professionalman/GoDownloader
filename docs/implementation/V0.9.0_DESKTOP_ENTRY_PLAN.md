### C. Event Flow

- **Finding:** Sequenced events carry monotonic integer cursors. State synchronization in `App.tsx` applies events when `seq > lastAppliedCursorRef.current` and triggers rehydration when `sync.required` is received.

- **Trace Path:** `http.Server.Close()` -> `cancel()` -> `manager.Stop()` -> `processSupervisor.Shutdown(shutdownCtx)` -> `db.Close()`.
- **Finding:** `manager.Stop()` terminates active job monitoring, cancels active job contexts, and stops the scheduler. `processSupervisor.Shutdown()` terminates the Windows Job Object containing all child process trees. `db.Close()` flushes WAL checkpoints.

### E. Frontend Transport Flow
- **Search & Inspection:** `web/src/api.ts` exports all client methods and is the sole caller of `fetch()` and `EventSource` in the entire frontend.
- **Finding:** Complete encapsulation enables substituting `fetch` with native desktop IPC without modifying any React UI components.

## 5. Reusable Core vs. Web Transport Classification

To enable both desktop shell execution (`cmd/desktop`) and headless/integration execution (`cmd/server`) without code duplication, the codebase will be partitioned into **Reusable Application Core** and **Web Transport Glue**:

### A. Reusable Application Core (Retained & Encapsulated)
1. **Persistence & Transactions:** `database.DB`, all SQLite repositories (`Job`, `Queue`, `Settings`, `Secret`, `Tracker`, `Category`, `Execution`, `Torrent`), schema migrations, and pre-v0.8 backup safety.
2. **Master Key & Crypto:** `securestore.MasterKeyManager` (Windows Credential Manager provider), AES-256-GCM cipher resolution, `securestore.Store`, and `settings.SettingsService`.
3. **External Tools:** `toolmanager.ToolManager`, persistent tool ledger, provenance verification, health probes, and executable path resolution.
4. **Process Supervision:** `process.ProcessSupervisor`, Windows Job Object process-tree containment (`CREATE_SUSPENDED`, `AssignProcessToJobObject`, `ResumeThread`), and graceful termination.
5. **Download Engines:** `engine.Registry`, `aria2.Engine`, `qbittorrent.Engine`, and `ytdlp.Engine`.
6. **Domain Services:** `storage.StorageService` (disk preflight, category paths), `mediaauth.Service` (cookie decryption, temp file cleanup), and `tracker.Service` (tracker list scraping).
7. **Job Orchestration & StateSync:** `job.Manager`, `job.ResourceGovernor`, `job.Scheduler`, `events.InMemoryBus`, `FinalizationJournal` reconciliation, and startup job recovery.
8. **Deterministic Lifecycle:** LIFO shutdown order (`manager.Stop()` -> `processSupervisor.Shutdown()` -> `db.Close()`).

### B. Web Transport Glue (Eliminated or Optional in Desktop Shell)
1. **HTTP Routing & Multiplexing:** Gorilla `mux.Router`, route pattern matching, query parameter parsing, and path variable extraction.
2. **Web Security Middleware:** `api.SecurityManager`:
   - Host header validation (DNS rebinding prevention).
   - Origin / Localhost CORS validation (`rs/cors`).
   - CSRF token generation and header validation (`X-CSRF-Token`).
   - Session cookie generation and validation (`godownloader_session`, `godownloader_csrf`).
3. **HTTP Streaming Transport:** `events.SSEHandler`, chunked HTTP SSE encoding, `Last-Event-ID` parsing, and SSE connection keep-alives.
4. **HTTP Server Socket:** `http.Server`, loopback TCP listener (`127.0.0.1:8080`), and socket shutdown.
5. **Static File Server:** `spaHandler` and `http.FileServer` serving compiled HTML/JS/CSS over HTTP.
6. **Web-to-OS Helpers:** `api.openFolder` via `os/exec.Command("explorer", dir)` (replaced by native desktop shell API).

## 7. Reduced Spike Binding Scope (Minimal Architectural Proof)

To keep `SPK-SYN3-01` focused on proving framework viability without premature over-engineering, the spike will **NOT** bind all 44+ endpoints.

The spike will bind only the minimal set required to prove each critical architectural capability:

1. **Read Operation:**
   `GetSyncSnapshot()` — Proves serialization of complex domain models (`Job`, `QueueSnapshot`) across Go -> TypeScript boundary.
2. **Mutation Operation:**
   One safe representative deterministic operation (e.g. `RunNowJob(id)` or `PauseJob(id)`) — Proves typed parameter passing, error translation, and domain state modification.
3. **Event Delivery:**
   One existing `Job`/`Event` payload (e.g. `job.updated`) — Proves native Go -> WebView2 event dispatch without HTTP SSE.
4. **Lifecycle Operation:**
   Explicit `Quit` — Proves user-initiated shutdown cleanly triggers `app.Shutdown()`.

The full 46-endpoint map in Section 6 remains the reference specification for staged post-spike implementation.

## 10. StateSync Spike Boundary & Native Event Strategy

Do **not** recreate HTTP SSE over Wails events. The native event bridge will preserve existing `FND-2B` semantics:

```text
Backend Event Bus (InMemoryBus)
       │
       ├──> Desktop Event Bridge (runtime.EventsEmit)
       │         │
       │         ▼
       │    Wails Native IPC Channel (window.runtime.EventsOn)
       │         │
       │         ▼
       │    Frontend StateSync Consumer (App.tsx)
       │         │
       │         ├── 1. Deduplicate via sequence cursor (seq <= lastAppliedCursorRef)
       │         ├── 2. Upsert/Remove job in React state
       │         └── 3. If "sync.required" received:
       │                 ├── Invalidate live continuity
       │                 ├── Fetch authoritative snapshot: DesktopService.GetSyncSnapshot()
       │                 ├── Atomically replace state & install snapshot.cursor
       │                 └── Re-arm event listener
```

### Invariants to Prove in Spike:
- Backend core remains alive across webview lifecycle.
- Frontend subscribes to native event bridge.
- Frontend obtains authoritative snapshot/cursor.
- Events use existing sequence semantics.
- Webview reload obtains a fresh authoritative snapshot.
- No duplicate `Manager`, `Scheduler`, or `DB` instance is created.

## 11. Single-Instance Strategy (Wails-Native First)

Running multiple host instances against a single data root risks SQLite WAL contention, concurrency governor desynchronization, and duplicate child process supervision.

### Policy:
- **PRIMARY:** Utilize and evaluate Wails v3 native `application.SingleInstanceOptions`.
  - On Windows, Wails v3 implements single-instance management using a named mutex and automatically forwards secondary launch data/arguments to the primary instance.
- **FALLBACK:** Custom OS-level Win32 named mutex and local named pipe IPC implementation, evaluated **only** if the spike reveals a concrete missing capability in the framework's native handling.

### Spike Verification Requirements:
1. Second process invocation does not create another GoDownloader core or open SQLite.
2. Command-line arguments forwarded from secondary launch reach the primary instance.
3. Primary window can restore from minimized/hidden state and gain OS focus.
4. Secondary process exits cleanly with exit code 0.
5. Database, scheduler, and ProcessSupervisor remain under strict single-process ownership.

## 12. Candidate Data Root & Invariant Verification

- **Current Baseline:** `cmd/server/main.go` uses `./downloader.db` and `./data`.
- **Candidate Desktop Location:** `%APPDATA%\GoDownloader` (e.g. `C:\Users\<User>\AppData\Roaming\GoDownloader`).
- **Required Invariant:** **One deterministic per-user data root**, independent of the process working directory.

### Spike Verification Requirements:
1. Database path resolves independently of current working directory.
2. Managed tool paths and tool ledger reside within the data root.
3. Staging and temporary paths remain deterministic.
4. Packaged launch from a read-only directory (such as `C:\Program Files`) is fully functional.
5. Secondary instance invocation resolves the exact same data root.

*(Note: Production config code is not modified in this planning checkpoint).*

## 14. Explicit Quit Mapping & Shutdown Lifecycle

When the user triggers explicit **Quit** from the system tray menu:

```text
[User clicks "Quit"]
         │
         ▼
[1. Tray & Window Teardown]
   - Hide tray icon & close WebView2 window
         │
         ▼
[2. App.Shutdown(ctx) - Bounded 5-10s Timeout]
   - Manager.Stop() [LIFO Step 1]
       * Cancels active job execution contexts
       * Flushes FinalizationJournal checkpoints
       * Halts scheduler and monitor loops
         │
   - ProcessSupervisor.Shutdown(shutdownCtx) [LIFO Step 2]
       * Closes Win32 Job Object handles
       * Terminates all child and grandchild yt-dlp / ffmpeg process trees
         │
   - Database.Close() [LIFO Step 3]
       * Flushes SQLite WAL checkpoints
       * Closes database connection cleanly
         │
         ▼
[3. Process Exit(0)]
   - Exits cleanly with zero orphans
```

## 15. Subsystem Compatibility Hypotheses

1. **ProcessSupervisor (`CREATE_NO_WINDOW` Hypothesis):**
   - Locked `FND-4B` containment remains: `CREATE_SUSPENDED` -> Start -> Assign Job Object -> verify containment -> `ResumeThread`.
   - **Spike Hypothesis to Test:** Determine whether `CREATE_NO_WINDOW` (`0x08000000`) is needed and compatible with supervised `yt-dlp` child execution in a GUI subsystem process to suppress console window flashing.
2. **SecureStore (Windows Credential Manager):**
   - `WindowsCredentialManagerProvider` uses `advapi32.dll`. Operates under the current user logon token. Works identically in GUI and console processes without elevation.
3. **ToolManager:**
   - Operates in-process, revalidating tool ledgers on startup without blocking UI rendering.
4. **External Engines (qBittorrent / aria2 / FFmpeg):**
   - Remain external user-managed dependencies accessed over loopback RPC or PATH. Missing tools disclose actionable UI diagnostics.

## 19. Wails Rejection Criteria

Wails v3 will be rejected **only** if the spike demonstrates a material architectural blocker, such as:
1. Native bindings cannot support the required DTO or operation model.
2. Native event bridge cannot support `FND-2B` StateSync monotonic ordering semantics.
3. Single-instance mechanism cannot guarantee a single GoDownloader core instance.
4. System tray or window lifecycle cannot support background download operation.
5. Explicit Quit cannot reliably trigger the GoDownloader ordered shutdown lifecycle.
6. `ProcessSupervisor` / Windows Job Object containment breaks under the desktop host.
7. Hosting React/Vite requires maintaining an unmaintainable framework fork.
8. Windows packaging or runtime has an unresolvable platform incompatibility.

*(Wails will NOT be rejected solely due to beta label, minor cosmetic limitations, missed arbitrary RAM targets, or missing custom tray polish).*
