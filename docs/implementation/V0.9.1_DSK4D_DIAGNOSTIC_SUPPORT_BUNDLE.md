## 5. Final Privacy Model: Default Deny & Data Minimization
The support bundle implements a strict **DEFAULT DENY** privacy boundary:
- **No Raw Database:** Zero `.db`, `.sqlite`, `-wal`, `-shm`, or `.bak` database files enter the archive.
- **No Credentials:** Zero Windows Credential Manager secrets, passwords, proxy credentials, auth tokens, master keys, or cookies.
- **No Application Logs:** Raw log files are excluded to prevent exfiltration of dynamic URLs, stack traces with personal paths, or user search queries.
- **No User Paths or Filenames:** Downloaded file names, destination directories, torrent content paths, and personal filesystem paths (`C:\Users\<username>`) are excluded or normalized.
- **No Raw URLs:** Download sources, query parameters, bearer tokens, API endpoints, tracker URLs, and magnet links are excluded.
- **No Untrusted Subprocess Strings:** Process IDs, process command line arguments, environment variables, `ToolInfo.Diagnostic`, and `ToolInfo.ExecutablePath` are omitted.

## 6. Build & Version Strategy
Package `internal/buildinfo` (`internal/buildinfo/buildinfo.go`) extracts truthful runtime identity using Go standard library `runtime/debug.ReadBuildInfo()`:
- `buildinfo.Current()` returns `Info{ Version: string, Commit: string }`.
- If `bi.Main.Version` is `""` or `(devel)`, it emits `"(devel)"`.
- It never hardcodes `"0.9.1"` or parses `build/config.yml`.
- It never executes `git` via subprocess at runtime.
- Git revision is sanitized via `SanitizeRevision`: validated as lowercase hex `^[0-9a-f]{7,40}$`, appending `"-dirty"` if `vcs.modified == "true"`, and falling back to `"unknown"`.

## 9. Host Snapshot Architecture & Truthful Data-Root
GoDownloader desktop resolves its data root canonically from `%APPDATA%\GoDownloader` (`cmd/desktop/data_root.go`). Support bundle emits only the normalized token `%APPDATA%\GoDownloader` without inspecting temporary directories or inferring physical paths.
Passed via `supportbundle.HostSnapshot`:
- `DataRootKind`: Truthfully reports `"appdata"`.
- `DataRootNormalized`: Sanitized logical token `"%APPDATA%\\GoDownloader"` (scrubbing all Windows user profile paths and usernames).
- `CloseToTray`: Current boolean lifecycle state.
- `AutostartEnabled`: Current Windows registry autostart state.

## 13. Safe Version Normalization
`supportbundle.NormalizeToolVersion(raw string) string`:
- Enforces maximum input length of 256 bytes.
- Takes first line only, stripping carriage returns and newlines.
- Parses ffmpeg version banners (extracts third field after `ffmpeg version`).
- Strips leading `v`/`V` if followed by a digit.
- Rejects any string containing slashes (`/`, `\`), colons (`:`), question marks (`?`), query parameters (`&`, `=`), at-signs (`@`), tildes (`~`), dollar signs (`$`), pipes (`|`), semicolons (`;`), or spaces.
- Matches against `^[A-Za-z0-9][A-Za-z0-9.\-+_]{0,47}$`.
- Returns `"unknown"` on any failure or invalid characters.

## 21. 1 MiB Uncompressed Cap
All 9 entry payloads are assembled in memory and their total uncompressed byte count is summed. If total uncompressed bytes exceed 1,048,576 bytes (1 MiB), the builder fails immediately before creating any destination file or temporary archive.

## 22. Same-Directory Staged Replacement Design
1. Selected destination directory is determined via `filepath.Dir(destinationPath)`.
2. Temporary sibling file created via `os.CreateTemp(dir, ".godownloader-support-*.tmp")`.
3. ZIP writer streams the in-memory payloads to temp file.
4. ZIP writer closes; file handle is synced (`f.Sync()`) and closed.
5. Temp archive is validated (`zip.OpenReader`).
6. Staged same-filesystem replacement: `os.Rename(tmpPath, destinationPath)`.
   - **CRITICAL INVARIANT:** Existing destination is NEVER pre-deleted. No `os.Remove(destinationPath)` occurs prior to replacement.
   - Normal replacement failure preserves existing destination completely intact.
   - Windows standard library `os.Rename` is truthfully described as staged same-filesystem replacement after complete validation; it is not claimed crash-level atomic.
7. Temp file removal is deferred and cleaned up immediately if any error occurs.

## 23. Overwrite Semantics
The native Windows Save File Common File Dialog provides the authoritative system prompt (`FOS_OVERWRITEPROMPT`) asking the user for confirmation before returning the path. DesktopService respects this prompt without presenting redundant duplicate UI modals.

## 24. Cancellation Semantics
If the user cancels the Save File dialog, `PromptForSingleSelection()` returns empty string `""` with `nil` error.
`DesktopService.ExportSupportBundle()` detects this and returns:
```json
{ "status": "cancelled" }
```
No temporary files are created on disk, no builder execution occurs, and frontend displays a neutral cancellation message without triggering error alerts.

---

## 25. Destination-Path Privacy
The chosen filesystem destination path is used exclusively within `DesktopService` and `supportbundle.Builder` to write the output archive. It is never included in the archive itself, never persisted in settings or logs, and never returned to the frontend. The frontend receives only the base filename (`filepath.Base(destinationPath)`).
