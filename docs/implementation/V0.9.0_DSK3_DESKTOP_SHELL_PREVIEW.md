## 1. Executive Summary & Verdict

Milestone **DSK-3** (`DESK-1 — Shell Preview`) introduces the first production Windows desktop host (`cmd/desktop`) for GoDownloader, realizing the accepted Wails v3 architecture evaluated in `SPK-SYN3-01`.

Following comprehensive review, two critical lifecycle and synchronization gates were identified and hardened:
1. **Hard Gate A (Single-Instance Pre-Core Ordering):** Secondary desktop processes are guaranteed never to construct duplicate runtime instances, open SQLite databases, or start supervisory goroutines. Wails v3 single-instance mutual exclusion is established prior to `app.New()` and `app.Start()`. Secondary processes terminate cleanly with exit code 0 inside `application.New()`.
2. **Hard Gate B (Native StateSync Catchup Handshake):** The potential race condition where mutations occur between snapshot retrieval and native event listener registration is closed deterministically via `DesktopService.GetEventsAfter(cursor)`. In-flight live events are queued during the handshake, replayed events are processed first, and live events are drained with sequence deduplication. Ephemeral progress events (`seq=0`) pass unconditionally without disturbing monotonic sequence state.

### Key Outcomes:
1. **Core Reuse Without Duplication:**
   `cmd/desktop` initializes the exact application runtime extracted in `DSK-1` (`internal/app.New`, `Start`, and `Shutdown`). The desktop host wires no duplicate repositories, engines, or schedulers. Exactly one `App` instance exists per primary process.
2. **Deterministic Single-Instance Mutual Exclusion:**
   Secondary processes exit with code 0 inside `application.New()` before any core runtime or database initialization can occur. Core initialization count is strictly 1 regardless of repeated secondary launches. Arguments and working directories are forwarded cleanly over native IPC.
3. **Embedded Production React Application:**
   The production React application is built via Vite multi-page configuration into `web/dist`, producing both `dist/index.html` (for server web mode) and `dist/desktop.html` (for desktop mode). Assets are embedded directly into the Go binary via standard library `//go:embed` in `web/embed_production.go` (`//go:build production`) and served in-process by Wails `application.AssetFileServerFS`. A dev build fallback in `web/embed_dev.go` (`//go:build !production`) provides an empty `embed.FS` so that `go test ./...` and developer builds succeed on clean checkouts without requiring pre-built frontend artifacts.
4. **Framework-Neutral Transport Realization:**
   `web/src/desktop.tsx` synchronously installs `desktopBackendClient` (`web/src/transport/desktop.ts`) into the framework-neutral client slot before React mounts (`mountApp()`). Shared React components execute zero runtime host-checking or browser-sniffing branches.
5. **Native Typed IPC:**
   All 7 domain namespaces (`jobs`, `queue`, `settings`, `categories`, `tracker`, `mediaAuth`, `sync`) are exposed by `DesktopService` (`cmd/desktop/service.go`) and invoked through auto-generated Wails v3 bindings (`web/src/bindings/downloader/cmd/desktop/desktopservice.ts`).
6. **Native StateSync & Live Event Streaming:**
   The `App.EventBus()` fan-out channel is bridged into Wails native events (`godownloader.event`). The desktop client subscribes via `@wailsio/runtime` `Events.On`, maintaining cursor progression, snapshot hydration, gap detection (`seq > cursor + 1` triggers `sync.required`), catchup replay via `GetEventsAfter`, and rehydration without HTTP polling.
7. **Zero Listening Localhost Sockets:**
   Normal desktop operation starts no HTTP server, Gorilla mux router, or SSE listener. Process port audits confirm **zero listening TCP ports**.
8. **Clean Shutdown:**
   Desktop window close (`WM_CLOSE`) or explicit `Quit` executes `App.Shutdown(ctx)`, cleanly terminating supervised processes, flushing SQLite WAL, and releasing resources with exit code 0.

## 3. Hardening Details

### A. Hard Gate A: Single-Instance Pre-Core Ordering
- **Mechanism:** In Wails v3, single-instance mutual exclusion is managed by `newSingleInstanceManager(options.SingleInstance)`. Crucially, this manager is created and executed synchronously inside `application.New(options)`. If a secondary instance is detected, the manager forwards launch data via named pipe to the primary and calls `os.Exit(0)` before `application.New` returns.
- **Ordering Guarantee:** By placing `application.New(...)` before `app.New()` and `app.Start()` in `cmd/desktop/main.go`, secondary processes exit immediately inside `application.New()`. They never reach runtime configuration, SQLite open, secret key generation, ProcessSupervisor initialization, or disk directory creation.
- **Verification:** An atomic counter (`globalCoreInitCount`) tracks core runtime instantiations in the process. Combined with `single_instance_status.json` persisted to the data root, runtime tests prove:
  - Primary start: Core init count = 1.
  - Secondary launch 1: Core init count = 1, second launch count = 1, forwarded args/CWD captured.
  - Secondary launch 2: Core init count = 1, second launch count = 2, forwarded args/CWD captured.

### B. Hard Gate B: Native StateSync Catchup Handshake
- **Problem:** If a state mutation occurs after the frontend retrieves a `SyncSnapshot` with cursor $C$ but before the frontend registers the native event listener, an event with sequence $C+1$ could be lost. If no subsequent event occurs, live gap detection (`seq > cursor + 1`) would never fire, leaving the UI permanently desynchronized.
- **Solution:**
  1. `DesktopService.GetEventsAfter(cursor int64)` queries `EventBus.GetEventsAfter(cursor)` to retrieve events between the client cursor and the current server cursor.
  2. `DesktopEventSubscription` attaches the native `Events.On('godownloader.event')` listener immediately upon instantiation to ensure no future live events escape.
  3. Live events arriving while `GetEventsAfter` is in flight are buffered in an internal queue (`pendingLiveEvents`).
  4. Once `GetEventsAfter` resolves:
     - If a ring-buffer gap occurred (`gapDetected: true`), `onSyncRequired({ cursor, reason: 'event_gap' })` is invoked immediately.
     - Otherwise, replayed events are emitted in strict order to `onEvent`, advancing the subscription's internal `lastProcessedSeq`.
     - Queued live events are then drained with sequence deduplication (`seq <= lastProcessedSeq` discarded, `seq > lastProcessedSeq + 1` triggering `sync.required`).
  5. **Ephemeral Sequence Handling:** Ephemeral progress events (`sequence: 0` or undefined) pass through unconditionally without updating `lastProcessedSeq` or tripping gap detection.
- **Verification:** Unit tests simulate a snapshot at cursor 100, a mutation producing event 101, listener registration, and NO subsequent event 102. The handshake replays event 101 deterministically without timing dependencies.
