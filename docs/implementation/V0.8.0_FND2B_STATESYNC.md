#### 2.1 Authoritative Snapshot Contract
- The backend SQLite database is the sole authoritative source of truth.
- `GET /api/v1/sync/snapshot` performs a lock-free optimistic snapshot with lower-bound watermark fallback:
  1. Reads $c_1 = \text{GetCurrentCursor()}$.
  2. Reads `jobs = List()` and `queue = GetQueueSnapshot()`.
  3. Reads $c_2 = \text{GetCurrentCursor()}$.
  4. If $c_1 == c_2$, the snapshot is atomic. If $c_1 \ne c_2$ after retries, $c_1$ is returned as the conservative watermark.
  5. Any mutations with sequence $> c_1$ are guaranteed to be delivered via replay buffer or live SSE stream.

#### 2.2 Bounded Replay & Rehydration Policy
- **Capacity:** Fixed capacity of 256 events in memory.
- **Filtering:** Only durable mutations (`Sequence > 0`) enter the replay buffer.
- **Contiguity Proof:** When a client reconnects with cursor $N$:
  - If $N == C$: client is up to date, stream live.
  - If $N < C$ and all events $N+1 \dots C$ are in buffer: contiguous replay sent with `id: <seq>`, followed by seamless transition to live stream.
  - If $N < C$ and buffer has evicted $N+1$, or buffer is empty (e.g. server restart): emit `event: sync.required\ndata: {"cursor": C, "reason": "..."}\n\n`.
  - If $N > C$: client cursor in the future: emit `event: sync.required`.
  - If slow subscriber channel drops events: detected via `event.Sequence > lastSentSeq + 1`, emitting `event: sync.required`.

#### 2.3 Ephemeral Telemetry Boundary
- High-frequency progress updates (250ms ticks from yt-dlp or aria2) where `persistNow == false` emit `EventJobUpdated` with `Sequence = 0`.
- Ephemeral ticks do not touch SQLite, do not advance `event_cursors`, do not enter `ReplayBuffer`, and do not output `id:` in SSE. The browser's `lastEventId` is never corrupted.
- Periodic persisted progress writes (`persistNow == true`, every 3s) advance the durable cursor and carry `Sequence > 0`.

#### 2.4 Deleted Job Retention Bug Resolution
- `replaceJobsFromInitialLoad` previously merged current in-memory jobs on top of loaded jobs, causing jobs deleted on the server to be resurrected in client state.
- Replaced with `reconcileJobsFromSnapshot`: only jobs present in the authoritative snapshot are retained. Stale/deleted jobs in client memory are cleanly pruned.

## Final Continuity / Rehydration Verification

### 1. Final `sync.required` Stream Behavior
- **Previous Behavior:** When `SSEHandler.ServeHTTP` encountered `cursor_ahead_of_server`, `replay_gap_or_buffer_overflow`, or `slow_subscriber_gap_detected`, it called `h.emitSyncRequired(w, flusher, ...)` but remained inside the `for { select { ... } }` loop, continuing to deliver live events on the existing connection.
- **Final Behavior:** `SSEHandler.ServeHTTP` now returns immediately (`return`) after emitting `event: sync.required`. Returning triggers `defer h.bus.Unsubscribe(ch)` to immediately clean up the event bus subscription, terminates the streaming HTTP response, and closes the TCP connection from the server side.

### 2. Frontend Rehydration & Old-Stream Invalidation Behavior
- **Previous Behavior:** Frontend `api.ts` listened to `sync.required`, but did not close the native `EventSource`. While `handleSyncRequired` was asynchronously fetching `getSyncSnapshot()`, live events on the still-open SSE connection could update in-memory jobs and advance `lastAppliedCursorRef.current`, only to have `reconcileJobsFromSnapshot` overwrite them with an older snapshot while leaving the cursor high, permanently losing interim mutations.
- **Final Behavior:**
  1. `connectSSE` in `web/src/api.ts` synchronously invokes `es.close()` immediately upon receiving `sync.required`, preventing automatic background reconnects with a stale cursor.
  2. In `web/src/App.tsx`, `handleSyncRequired` closes any active `EventSource`, sets `connectionState` to `'reconnecting'`, fetches `snapshot = await getSyncSnapshot()`, and atomically applies snapshot state and cursor.
  3. Reconnection is triggered via `streamTrigger` state, initiating a new `connectSSE` call configured with `?cursor=${snapshot.cursor}`.

### 3. Cursor Non-Regression & Stale-Hydration Protection
- **Cursor Non-Regression:** `lastAppliedCursorRef.current` is strictly monotonic. During live streaming, `handleEvent` deduplicates events: any event where `seq <= lastAppliedCursorRef.current` is ignored. During rehydration, the stream is closed prior to fetching the snapshot, and `lastAppliedCursorRef.current` is atomically initialized to `snapshot.cursor`.
- **Stale-Hydration Protection:** `rehydrationGenRef` acts as a generation token. Every rehydration attempt increments `rehydrationGenRef.current`. When `getSyncSnapshot()` resolves, if `gen !== rehydrationGenRef.current` (e.g., due to an overlapping rehydration request or rapid reconnection), the stale snapshot response is safely discarded without mutating client state or regressing the cursor.

### 5. Snapshot Double-Read Consistency Conclusion
- The optimistic double-read protocol in `Manager.GetSyncSnapshot` reads $c_1 \to \text{read data} \to c_2$.
- When $c_1 \ne c_2$ after retries, $c_1$ is returned as the conservative lower-bound watermark.
- Any mutations occurring concurrently (either after $c_1$ before read, or after read before $c_2$) are assigned sequence numbers $> c_1$ in SQLite.
- Because $c_1$ is returned to the client, when the client connects or reconnects with `?cursor=c_1`, the server's `ReplayBuffer` contiguously delivers all events with sequence $> c_1$.
- This guarantees convergence with zero permanently hidden mutations, validated by `TestStateSync_SnapshotDoubleReadProof_InterleavedMutations`.

### 6. Replay / Live Subscription Race Conclusion
- `SSEHandler.ServeHTTP` subscribes to the event bus channel (`ch := h.bus.Subscribe()`) *before* querying the replay buffer or current cursor.
- Any live event published during replay buffer inspection is queued into `ch`.
- `lastSentSeq` tracks the highest sequence delivered during replay. As live events are drained from `ch`, any event with `event.Sequence <= lastSentSeq` is skipped.
- Zero events are lost, duplicates are deterministically filtered, proven by `TestSSEHandler_ReplaySubscriptionRace_NoMissingEvents`.
