### 2. Roadmap Requirements & Scope Boundaries

Under the locked roadmap for V0.9.1 Windows Desktop Beta:
1. **External Process Ownership Invariant:** GoDownloader never spawns, manages lifecycle, kills, or alters the process configuration of `qbittorrent.exe`. The qBittorrent daemon remains user-managed.
2. **OS-Protected Credential Storage:** The qBittorrent Web API password must be stored strictly using `SecureStore` (backed by Windows Credential Manager via `WindowsCredentialManagerProvider` using `CredWriteW` / `CredReadW` protecting the AES-GCM master key on Windows) and never in plaintext inside `app_settings` or DTO responses.
3. **Canonical Fallback Endpoint:** Canonical fallback endpoint remains `http://127.0.0.1:8081` with username `admin` and empty password. There is zero collision with GoDownloader's own server port (`127.0.0.1:8080`).
4. **Environment Precedence:** Environment variables (`QBIT_URL`, `QBIT_USERNAME`, `QBIT_PASSWORD`) take highest priority at runtime, but environment passwords must never be persisted to `SecureStore`.
5. **Ownership & Reconciliation Truthfulness:**
   - Owned same-infohash: Reattach to the existing torrent in qBittorrent if local database ownership is proven.
   - Ambiguous / unowned same-infohash: Must be **REFUSED BY DEFAULT** with `ErrTorrentAlreadyExistsExternally`. The dangerous silent adoption path (`AdoptTorrent`) is completely removed from production execution.
   - Foreign torrents: Must remain completely untouched (zero pause, resume, delete, retag, recategorize, priority change, or file-selection mutation).
6. **Shared-Mode Global Settings Safety:** In `ExternalUserManaged` mode, daemon-wide global network settings are disabled and unavailable. `ManageQBitGlobalNetworkSettings` is forced to `false`, and `reconcileManagedTorrentProxy` will never invoke `ApplyManagedProxy`.
7. **Pure Endpoint Validation & Compatibility Verification:**
   - Pure URL validator `ValidateQBitEndpoint` validates http/https, non-empty host, rejects embedded userinfo/passwords, rejects query and fragment parameters, and normalizes trailing slashes.
   - Compatibility validation checks qB >= 5.x, Web API >= 2.x, and executes a bounded read-only capability sanity probe against `/api/v2/torrents/info?limit=1`.
8. **Restart Required Semantics:** Settings changes are persisted safely and take effect upon GoDownloader restart, avoiding race conditions or mutations of active engine instances while torrent jobs are in flight.
9. **Credential-Resolution Error Handling & Fail-Closed Policy:**
   - Unconfigured qB credentials are a normal operational state (empty password returned, no error).
   - Genuine repository, endpoint validation, or SecureStore decryption failures return non-nil errors without leaking secrets.
   - `App.New` fails closed on genuine credential-resolution errors, preventing unauthenticated startup or silent credential fallback.

### 4. Credential Storage Architecture & Key Contract

#### 4.1 Credential Source Before vs. After
- **Before:** qBittorrent URL, username, and password were read exclusively from static flags / env config during startup (`cfg.QBitURL`, `cfg.QBitUsername`, `cfg.QBitPassword`). Runtime settings did not expose or persist qB credentials.
- **After:**
  - Endpoint URL: Persisted in `app_settings` under key `qbittorrent_url` (canonical fallback: `http://127.0.0.1:8081`).
  - Username: Persisted in `app_settings` under key `qbittorrent_username` (canonical fallback: `admin`).
  - Password: Stored exclusively via `SecureStore` in the `encrypted_secrets` table.
  - Runtime DTO: Surfaces `QBitSettings` containing `url`, `username`, `hasPassword` (boolean), and environment override flags. Plaintext password is never returned.

#### 4.2 SecureStore Schema & Key Contract
- **Storage Table:** `encrypted_secrets` (AES-256-GCM encrypted ciphertext protected by MasterKey).
- **Windows Master Key Provider:** `WindowsCredentialManagerProvider` using Win32 `CredWriteW`, `CredReadW`, and `CredDeleteW` from `advapi32.dll`.
- **Scope:** `settings` (`SecretScopeSettings = "settings"`)
- **Owner ID:** `global` (`SecretOwnerGlobal = "global"`)
- **Field Name:** `qbittorrent_password` (`SecretFieldQBitPass = "qbittorrent_password"`)

#### 4.3 `cfg.QBit*` Caller Audit & Precedence Contract
An audit of all callers and references across the codebase revealed:
- `cmd/server/main.go` and `cmd/desktop/main.go` do not mutate `cfg.QBit*` prior to `App.New`.
- The only test mutating `cfg.QBitURL` was `TestApp_NoProbeOnContention` (which tests lock contention prior to engine creation).
- To preserve host-level programmatic injection without drifting defaults, `GetEffectiveQBitCredentials` accepts an optional `QBitFallback` struct (`URL`, `Username`, `Password`). If `cfg` contains custom (non-canonical default) values, they are cleanly used as the programmatic fallback tier.

**Final 4-Tier Precedence Hierarchy:**
1. **Tier 1 (Highest): Explicit Environment Variables:** `QBIT_URL`, `QBIT_USERNAME`, `QBIT_PASSWORD`.
2. **Tier 2: Persisted Settings & SecureStore:** `qbittorrent_url` and `qbittorrent_username` from `app_settings`, and `qbittorrent_password` from `SecureStore`.
3. **Tier 3: Programmatic Fallback:** Non-default values passed via `cfg` (`QBitFallback`).
4. **Tier 4 (Lowest / Baseline): Canonical Hardcoded Fallback:**
   - URL: `config.DefaultQBitURL` (`http://127.0.0.1:8081`)
   - Username: `config.DefaultQBitUsername` (`admin`)
   - Password: `""`

**Security Invariant:** When `QBIT_PASSWORD` is supplied via environment, it is used purely in-memory at runtime and is **NEVER** copied or persisted into `SecureStore`.

#### 4.4 Error-Handling Contract & Fail-Closed Lifecycle
In `SettingsService.GetEffectiveQBitCredentials(ctx, fallback ...QBitFallback)`:
- **Missing persisted qB password:** Treated as normal unconfigured state; returns `password = ""` and `nil` error.
- **No persisted qB settings:** Treated as normal unconfigured state; returns canonical/programmatic fallback and `nil` error.
- **Repository read failures:** Returns wrapped error (`fmt.Errorf("read persisted qbittorrent url: %w", err)`).
- **Endpoint validation failures:** Returns error from `ValidateQBitEndpoint(rawURL)` (`fmt.Errorf("invalid effective qbittorrent url: %w", err)`).
- **SecureStore / Decryption failures:** When `secrets.Has(...)` indicates a secret is present but `secrets.Get(...)` fails, returns sanitized error (`fmt.Errorf("retrieve qbittorrent password: %w", err)`).
- **Secret Sanitization:** All returned and logged error strings are strictly free of password plaintext, ciphertexts, or authentication tokens.

In `App.New`:
```go
effectiveQBitURL, effectiveQBitUser, effectiveQBitPass, err := settingsService.GetEffectiveQBitCredentials(ctx, settings.QBitFallback{
    URL:      cfg.QBitURL,
    Username: cfg.QBitUsername,
    Password: cfg.QBitPassword,
})
if err != nil {
    return nil, fmt.Errorf("resolve qBittorrent connection settings: %w", err)
}
```
- **Fail-Closed Result:** Genuine credential-resolution failure halts `App.New` and prevents startup. It does NOT silently fall back to an empty password.
- **Truthful Effective Endpoint Logging:**
  `log.Printf("qBittorrent engine: available at %s", effectiveQBitURL)`
  Diagnostics log the actual effective endpoint provided to `NewEngine` (reflecting persisted settings or environment overrides), rather than static `cfg.QBitURL`.

#### 4.5 Restart-Required Lifecycle
- When the user updates qBittorrent connection settings in the UI or API, `UpdatePowerSettings` validates the payload and writes the updated URL, username, and password (to `SecureStore`).
- The running `qbittorrent.Engine` instance is **NOT** swapped or mutated in-flight to prevent corruption of active background torrent jobs.
- The UI displays an explicit informational notice:
  `"Restart GoDownloader to apply qBittorrent connection changes."`
- Upon restart, `App.New` resolves effective credentials from `SettingsService` and initializes the engine with the updated credentials.

### 5. Validation Architecture

#### 5.1 Pure Endpoint Validation (`ValidateQBitEndpoint`)
Validates endpoint strings prior to persistence:
- Must parse as a valid URI.
- Scheme must strictly be `http` or `https`.
- Host must not be empty.
- Userinfo (embedded username or password) is rejected to prevent credential leaks.
- Query parameters (`?token=secret`, `?`) are strictly rejected (`u.RawQuery != ""` or `u.ForceQuery`).
- URL fragments (`#fragment`) are strictly rejected (`u.Fragment != ""`).
- Reverse proxy subpaths (e.g. `/qbittorrent`) remain supported and trailing slashes are cleanly normalized.
- Supports loopback (`127.0.0.1:8081`, `localhost`) as well as remote LAN/WAN endpoints.

#### 5.2 Version & Capability Sanity Probe
`qbittorrent.ValidateCompatibility(ctx, client)`:
1. Authenticates against `/api/v2/auth/login`.
2. Queries qBittorrent version (`/api/v2/app/version`) and asserts major version >= 5.
3. Queries Web API version (`/api/v2/app/webapiVersion`) and asserts major version >= 2.
4. Executes bounded read-only capability sanity probe against `/api/v2/torrents/info?limit=1` to verify functional torrent query capability.
5. Returns typed error codes (`ErrQBitEndpointInvalid`, `ErrQBitUnreachable`, `ErrQBitAuthFailed`, `ErrQBitVersionUnsupported`, `ErrQBitAPIUnsupported`) without leaking passwords, session cookies, or raw authorization data.

### 6. Same-Infohash Ownership & Reconciliation Matrix

| Condition in qBittorrent | Local DB State | Outcome | Reason |
|:---|:---|:---|:---|
| Same hash, category `godownloader`, matching job tag | Local job ID matches | **Reattach / Reuse** | Proven local ownership; seamless recovery. |
| Same hash, category `godownloader`, different job tag | Different local job exists | **REFUSED** (`ErrTorrentAlreadyManaged`) | Conflict; belongs to another local job. |
| Same hash, category != `godownloader` | Any | **REFUSED** (`ErrTorrentAlreadyExistsExternally`) | Foreign torrent; GoDownloader never touches. |
| Same hash, category `godownloader`, unknown/no job tag | No matching local job | **REFUSED** (`ErrTorrentAlreadyExistsExternally`) | Ambiguous orphan; zero silent adoption. |
| HTTP 409 conflict during add torrent | Re-query torrent tags | Follows same rules above | Prevents race condition hijacking. |

**Disposition of `AdoptTorrent`:** Removed from all production execution paths in `internal/job/manager.go`. Ambiguous and orphaned torrents are strictly rejected by default.

### 7. Global Settings & Foreign Torrent Safety

1. **Global qB Settings Disabled in Shared Mode:**
   - `getPowerSettings` and `UpdatePowerSettings` unconditionally enforce `ManageQBitGlobalNetworkSettings = false`.
   - `ValidateUpdate` explicitly rejects any request that attempts to set `ManageQBitGlobalNetworkSettings = true`.
   - `reconcileManagedTorrentProxy` in `internal/job/network_controls.go` returns immediately without executing `ApplyManagedProxy`.
2. **Foreign Torrent Immutability:**
   - Torrent operations are strictly partitioned by category and job tag.
   - Operations never pause, resume, delete, retag, recategorize, or adjust priorities/files for torrents not owned by GoDownloader.
3. **No qB Process Ownership:**
   - No code spawns, terminates, or monitors the OS process lifecycle of `qbittorrent.exe`.
